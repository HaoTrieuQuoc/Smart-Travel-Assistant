Algorithm 1.1 — Idempotent SHA-256 Check-Diff
Thuật toán Chống ghi trùng lặp & Phát hiện sửa đổi

Thay vì mù quáng ghi đè toàn bộ 1000 dòng mỗi lần đồng bộ, hệ thống sử dụng hàm băm mật mã SHA-256 để nhận biết dòng nào thực sự bị thay đổi:

// 1. Kết hợp 7 trường bất biến/quan trọng thành chuỗi đại diện const hashString = `${tripId}|${name}|${email}|${flight}|${iata}|${depTime}|${pnr}`; // 2. Sinh mã băm 64 ký tự hex (256-bit) const newHash = crypto.createHash('sha256').update(hashString).digest('hex'); // 3. So sánh với DynamoDB (Idempotency Check) if (existingItem && existingItem.row_hash === newHash) { skippedCount++; // Run 2: 6 skipped, 0 DB writes! } else { await putItemToDynamoDB(row, newHash); // Chỉ ghi khi có Diff updatedCount++; }

Kết quả kiểm chứng thực tế: Run lần 1 cập nhật 6 dòng; Run lần 2 khi không sửa Sheet → 0 dòng ghi đè, 6 dòng bỏ qua.

Algorithm 2.1 — Slack 3-Second Rule Mitigation
Thuật toán Phản hồi Bất đồng bộ (Decoupled Async ACK)

Slack quy định bất kỳ Webhook nào không trả về HTTP 200 trong vòng 3,000 ms sẽ bị hủy bỏ và báo lỗi operation_timeout cho người dùng. Nhưng việc ghi Google Sheet + gọi AI mất 1.5s – 5s.

// Luồng xử lý ngay lập tức trong slack_server.js res.writeHead(200); res.end(); // Slack nhận OK trong ~50ms, không bao giờ timeout! // Đẩy tác vụ nặng xuống Event Loop nền processModalInBackground(payload).catch(console.error);

Algorithm 3.1 — Sliding Time-Window & State Machine
Thuật toán Lọc Cửa sổ 24h & Chống Gửi Trùng Lặp

Hệ thống áp dụng máy trạng thái (State Machine) kết hợp cửa sổ thời gian trượt để đảm bảo mỗi nhân viên chỉ nhận được duy nhất 1 tin nhắn nhắc nhở trước giờ bay đúng 24 giờ:

const now = new Date(); const windowEnd = new Date(now.getTime() + 24 * 60 * 60 * 1000); // Điều kiện kích hoạt (Guard Clause) const shouldNotify = booking.status === 'APPROVED' && booking.reminder_sent !== 'SENT' && (depTime >= now && depTime <= windowEnd); // Chuyển trạng thái ngay sau khi gửi thành công // PENDING ──[Slack DM OK]──► SENT (Idempotent Lock)

Algorithm 4.1 — Defensive JSON Sanitizer
Thuật toán Trích xuất JSON An toàn từ Đầu ra LLM

Các mô hình ngôn ngữ lớn (LLM) thường bọc JSON trong khối markdown (```json ... ```) hoặc thêm lời chào ở đầu/cuối. Nếu dùng JSON.parse() trực tiếp sẽ gây sập hệ thống. Thuật toán Sanitizer xử lý triệt để vấn đề này:

function cleanJsonResponse(rawText) { let cleaned = rawText.trim(); // 1. Gỡ bỏ vỏ bọc markdown ```json cleaned = cleaned.replace(/^```json\s*/i, '').replace(/\s*```$/, ''); // 2. Định vị cặp ngoặc nhọn bao ngoài cùng { ... } const firstBrace = cleaned.indexOf('{'); const lastBrace = cleaned.lastIndexOf('}'); if (firstBrace !== -1 && lastBrace !== -1) { cleaned = cleaned.substring(firstBrace, lastBrace + 1); } return JSON.parse(cleaned); }
Figure 4.2 — Human-in-the-Loop Interactive Verification
Cơ chế Kiểm duyệt Thủ công Trước Khi Ghi Sổ (Human-in-the-Loop)

Dữ liệu tài chính & đặt chỗ trích xuất từ AI không được ghi thẳng vào cơ sở dữ liệu ngay mà đi qua 1 bước xác nhận tương tác:

  • Bước 1 (AI Extraction): Gemini Vision đọc ảnh vé và đóng gói thành object JSON 12 trường.
  • Bước 2 (Payload Embedding): Chuỗi JSON được nhúng trực tiếp vào thuộc tính value của nút bấm Block Kit confirm_save_ticket (không cần lưu session tạm trên RAM).
  • Bước 3 (1-Click Commit): Khi người dùng kiểm tra thấy đúng và bấm nút [✅ Xác Nhận & Lưu Vào Sheet], payload JSON từ nút bấm gửi về /slack/interactions để ghi đồng thời vào Google Sheets & DynamoDB.
