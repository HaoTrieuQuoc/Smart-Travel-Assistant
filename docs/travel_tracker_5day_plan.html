Project Implementation Blueprint

Dự Án: Travel Tracker (Slack AI & Workflow Automation)

Kế hoạch chi tiết xây dựng sản phẩm trong 5 ngày: Tự động hóa quản lý lịch trình công tác của các Sếp qua Slack, đồng bộ hai chiều Google Sheets & DynamoDB, kiểm toán dữ liệu tự động và tích hợp AI Agent đọc vé máy bay.

Giao diện chính: Slack (Modals, Slash Commands, DM & AI Agent)
Cloud Platform: AWS Serverless & Amazon Bedrock
Thời gian triển khai: 5 Ngày (Sprint MVP)
Đối tượng sử dụng: Biz Admin & Ban Giám Đốc (C-Level/Managers)

Kiến Trúc Luồng Hoạt Động (System Workflows)

Hệ thống bao gồm 4 luồng xử lý cốt lõi bám sát 8 yêu cầu nghiệp vụ của dự án:

Luồng 1: Daily Sync & Audit
(Yêu cầu 1, 2, 3, 6)
EventBridge (Daily Cron) → Lambda Sync Worker → Google Sheets API (Service Account) → Check Diff & Validate Format → Update DynamoDB + Báo lỗi vào Slack Channel Admin
Luồng 2: Admin Slash Command
(Yêu cầu 7)
Slack Slash Command (/travel-admin) → Slack Interactive Modal → API Gateway + Lambda → Ghi thẳng Google Sheets & DynamoDB + Trigger Test/Automate
Luồng 3: 24h Flight Reminder
(Yêu cầu 4, 5)
EventBridge Schedule → Lambda Reminder → Tra mã IATA + Amazon Bedrock (Tạo cẩm nang điểm đáp & đồ cần mang) → Gửi Email (Amazon SES) + Slack Bot DM
Luồng 4: Slack AI Agent & OCR
(Yêu cầu 8)
User Chat / Upload Ảnh Vé lên Slack → Lambda Agent Handler → Amazon Bedrock Vision (Trích xuất thông tin vé / Tạo PR) → Điền tự động vào Google Sheets & DynamoDB

Danh Mục Dịch Vụ AWS Cần Sử Dụng (AWS Tech Stack)

AWS Lambda Compute

Xử lý toàn bộ logic Serverless (Python 3.12) thông qua 4 hàm chuyên biệt:

  • travel-sheet-sync-fn: Đọc Google Sheets, so sánh hash diff, validate dữ liệu và cập nhật DynamoDB.
  • travel-slack-interactive-fn: Xử lý Slash Command, hiển thị/nhận dữ liệu từ Slack Modal.
  • travel-reminder-24h-fn: Quét chuyến bay trước 24h, gọi AI tạo nội dung và bắn thông báo.
  • travel-ai-agent-fn: Xử lý hội thoại tự nhiên, tạo Purchase Request (PR) và OCR ảnh vé.

Amazon DynamoDB Database

Cơ sở dữ liệu NoSQL lưu trữ dữ liệu chuyến đi đã đồng bộ từ Google Sheets:

  • Table TravelBookings: Partition Key trip_id, lưu thông tin chuyến bay, row_hash (để kiểm tra diff nhanh) và cờ reminder_sent.
  • GSI DepartureTimeIndex: Hỗ trợ truy vấn nhanh các chuyến bay sắp khởi hành trong vòng 24h.
  • Table PurchaseRequests: Lưu lịch sử yêu cầu tạo PR từ cuộc hội thoại với Slack Agent.

Amazon EventBridge Orchestration

Quản lý các tác vụ chạy tự động theo lịch (Cronjob & Scheduler):

  • Daily Sync Rule: Chạy cố định mỗi ngày (VD: 08:00 sáng) để kích hoạt Lambda kiểm tra diff từ Google Sheets và gửi báo cáo lỗi vào Slack Channel của Admin.
  • Reminder Check Rule: Chạy định kỳ mỗi 15-30 phút (hoặc dùng EventBridge Scheduler hẹn giờ chính xác cho từng chuyến bay) để kích hoạt thông báo trước 24h.

Amazon Bedrock Generative AI

Trái tim AI của hệ thống, sử dụng mô hình Claude 3.5 Sonnet (hoặc Amazon Nova Pro):

  • Multimodal Vision (OCR): Đọc ảnh chụp vé máy bay/boarding pass hoặc e-ticket PDF do người dùng tải lên Slack để bóc tách PNR, Số hiệu chuyến bay, Ngày giờ, Sân bay đi/đến.
  • IATA Travel Content Generator: Dựa vào mã IATA sân bay đáp (VD: NRT, SIN, HAN, SFO) sinh danh sách đồ cần mang theo, đặc sản, chỗ vui chơi, danh lam thắng cảnh.
  • Conversational Agent: Hiểu ý định người dùng khi chat để thu thập thông tin tạo Purchase Request.

Amazon API Gateway Networking

Cổng giao tiếp HTTP API kết nối Slack Platform với AWS Lambda:

  • Endpoint POST /slack/events: Nhận sự kiện tin nhắn, file ảnh vé máy bay và tương tác với AI Agent.
  • Endpoint POST /slack/interactions: Nhận payload từ Slash Command và khi Admin submit Interactive Modal.
  • Tích hợp cơ chế trả lời HTTP 200 OK trong vòng < 3 giây theo yêu cầu của Slack (kết hợp Lambda Async Invoke).

Amazon SES & Supporting Services Email & Security

Các dịch vụ bổ trợ hoàn thiện hạ tầng sản phẩm:

  • Amazon SES (Simple Email Service): Gửi email HTML chuyên nghiệp chứa thông tin chuyến bay, checklist hành lý và gợi ý điểm đến trước 24h.
  • AWS Secrets Manager: Bảo mật file JSON Google Service Account, Slack Bot Token và Signing Secret.
  • Amazon S3: Lưu trữ tạm thời file ảnh vé máy bay tải về từ Slack để phục vụ kiểm toán.
  • Amazon CloudWatch: Lưu log thực thi và cảnh báo khi job sync lỗi.

Ứng Dụng, Quyền Tích Hợp & Hạ Tầng Cần Chuẩn Bị (Apps & Infra)

1. Google Cloud & Google Sheets Setup Google Workspace

Để Slack Bot và AWS Lambda đọc/ghi trực tiếp vào file Google Sheets của Biz Admin:

  • Tạo Project trên Google Cloud Console, bật 2 API: Google Sheets API và Google Drive API.
  • Tạo Google Service Account, xuất khóa định dạng JSON và lưu vào AWS Secrets Manager.
  • Mở file Google Sheets quản lý chuyến đi, cấp quyền Editor cho địa chỉ email của Service Account (...@....iam.gserviceaccount.com).
  • Sử dụng thư viện Python gspread hoặc google-api-python-client trên Lambda Layer.

2. Cấu Hình Slack App (Bot, Modal & Agent) Slack Platform

Khởi tạo ứng dụng tại api.slack.com/apps với đầy đủ tính năng giao diện:

  • Slash Commands: /travel-manage (mở Modal thêm/sửa chuyến đi, chạy test sync thủ công).
  • Interactivity & Shortcuts: Bật để xử lý sự kiện bấm nút, chọn dropdown và submit Modal.
  • Agents & Assistants View: Bật chế độ AI App/Split-view để người dùng chat tạo PR hoặc thả ảnh vé máy bay.
  • Bot Token Scopes cần cấp: chat:write, im:write, commands, files:read, channels:read, users:read, users:read.email, assistant:write.

3. Bộ Công Cụ Phát Triển & IaC DevOps & SDK

Đảm bảo triển khai nhanh trong 5 ngày, dễ dàng quản lý môi trường Test/Prod:

  • IaC Framework: Sử dụng AWS SAM (Serverless Application Model) hoặc Serverless Framework để định nghĩa toàn bộ tài nguyên trong 1 file template.yaml.
  • Core Python Libraries:
    • slack-bolt: Framework chuẩn xử lý Modal, Slash Command, Events.
    • pydantic: Kiểm tra chặt chẽ định dạng ngày giờ, mã IATA, email, số tiền cho mục đích kiểm toán.
    • boto3: Tương tác DynamoDB, Bedrock, SES, Secrets Manager.

4. Chuẩn Hóa Schema & Quy Tắc Kiểm Toán Data Governance

Các trường bắt buộc kiểm tra khi chạy Daily Sync và nhập từ Slack Modal/AI:

  • Trip_ID (Unique ID), Passenger_Name, Passenger_Email, Slack_User_ID.
  • Flight_Code (Regex: ^[A-Z0-9]{2}\d{1,4}$, VD: VN214, VJ123).
  • Departure_IATA & Arrival_IATA (3 ký tự in hoa chuẩn IATA: SGN, HAN, NRT, SIN...).
  • Departure_Time (ISO 8601: YYYY-MM-DD HH:mm kèm Timezone).
  • PR_Number, Cost_Amount (Số dương), Audit_Status (VALID / MISSING_FIELD / INVALID_FORMAT).

Chiến Lược Thực Thi Dự Án Trong 5 Ngày (5-Day Execution Roadmap)

NGÀY 1: Thiết Lập Hạ Tầng, Google Sheets Sync & Báo Cáo Kiểm Toán
Giải quyết hạng mục: #1, #2, #3, #6

Công việc chi tiết trong ngày

  • Khởi tạo Google Service Account, cấp quyền vào file Google Sheets mẫu và lưu thông tin xác thực lên AWS Secrets Manager.
  • Dựng hạ tầng cơ bản bằng AWS SAM: Tạo bảng DynamoDB TravelBookings và hàm Lambda travel-sheet-sync-fn.
  • Viết thuật toán băm từng dòng (MD5/SHA256 row_hash) để so sánh diff: Chỉ cập nhật vào DynamoDB những dòng mới thêm hoặc có thay đổi trên Google Sheets.
  • Xây dựng bộ Validator bằng Pydantic kiểm tra các trường bị trống (missing fields) hoặc sai format (ngày giờ, mã IATA, giá tiền).
  • Tạo EventBridge Rule chạy hằng ngày và cấu hình Webhook gửi báo cáo danh sách các dòng lỗi (kèm số thứ tự dòng trên Sheet) vào Slack Channel của Biz Admin.

Kết quả bàn giao cuối Ngày 1

  • Pipeline đồng bộ Google Sheets → DynamoDB hoạt động ổn định.
  • Cơ chế Check Diff thông minh (không ghi đè dư thừa).
  • Báo cáo lỗi dữ liệu tự động đổ về Slack Channel mỗi ngày.
NGÀY 2: Xây Dựng Slack Bot, Slash Command & Interactive Modal Cho Admin
Giải quyết hạng mục: #7

Công việc chi tiết trong ngày

  • Tạo Slack App, cấu hình OAuth Scopes, Slash Commands (/travel-admin) kết nối qua API Gateway vào Lambda travel-slack-interactive-fn.
  • Thiết kế giao diện Slack Interactive Modal (Block Kit) cho phép Admin: (1) Thêm mới chuyến bay, (2) Chọn chuyến bay hiện có để sửa thông tin, (3) Bấm nút kích hoạt "Test Sync & Reminder" ngay lập tức.
  • Tích hợp kiểm tra định dạng ngay trên form Modal (Datepicker cho ngày bay, Dropdown/Regex cho mã sân bay IATA) để chặn lỗi nhập sai từ đầu.
  • Khi Admin bấm Submit trên Modal: Ghi trực tiếp vào đúng dòng trên Google Sheets đồng thời cập nhật ngay vào DynamoDB.

Kết quả bàn giao cuối Ngày 2

  • Admin thêm/sửa chuyến đi ngay trong Slack không cần mở Google Sheets.
  • Tính năng Test/Automate chạy thử ngay trên Modal hoạt động mượt mà.
NGÀY 3: Hệ Thống Nhắc Lịch 24h (Email & Slack DM) + AI IATA Travel Guide
Giải quyết hạng mục: #4, #5

Công việc chi tiết trong ngày

  • Cấu hình Amazon SES (xác thực domain/email gửi) và thiết kế mẫu HTML Email thông báo chuyến bay chuyên nghiệp.
  • Xây dựng module tích hợp Amazon Bedrock (Claude 3.5 Sonnet): Nhận đầu vào là mã IATA điểm đáp, ngày bay và thời gian lưu trú để sinh tự động:
    • Danh sách vật dụng cần mang theo (hộ chiếu, visa, ổ cắm chuyển đổi, trang phục theo thời tiết).
    • Cẩm nang đặc sản địa phương, địa điểm vui chơi và danh lam thắng cảnh nổi bật tại điểm đáp.
  • Viết Lambda travel-reminder-24h-fn kết hợp EventBridge: Quét các chuyến bay có giờ khởi hành trong 24h tới (mà reminder_sent = False), gửi đồng thời Email qua SES và nhắn tin trực tiếp (DM) qua Slack Bot cho người bay, sau đó đánh dấu reminder_sent = True.

Kết quả bàn giao cuối Ngày 3

  • Tự động bắn Email + Slack DM đúng 24h trước giờ bay.
  • Nội dung AI sinh theo mã sân bay IATA cá nhân hóa, trình bày đẹp mắt.
NGÀY 4: Xây Dựng Slack AI Agent, Tạo Purchase Request & Đọc Ảnh Vé Máy Bay
Giải quyết hạng mục: #8

Công việc chi tiết trong ngày

  • Kích hoạt tính năng Agent / Assistant cho Slack Bot, lắng nghe sự kiện tin nhắn trực tiếp (message.im) và tải file (file_shared).
  • Xây dựng luồng Multimodal Ticket OCR: Khi người dùng tải ảnh chụp hoặc PDF vé máy bay lên Slack, Lambda tải file qua Slack Token, đưa vào Amazon Bedrock Vision để bóc tách cấu trúc JSON (Họ tên, Hãng bay, Mã chuyến bay, PNR, IATA đi/đến, Ngày giờ bay, Giá vé).
  • Xây dựng luồng hội thoại Tạo Purchase Request (PR): Cho phép người dùng chat tự nhiên với Bot để yêu cầu tạo PR cho chuyến công tác; Agent tự động hỏi thêm các trường còn thiếu.
  • Hiển thị bản tóm tắt kèm nút "Xác nhận & Lưu" ngay trong khung chat để tự động ghi thông tin vé/PR vào Google Sheets và DynamoDB.

Kết quả bàn giao cuối Ngày 4

  • Bot đọc chính xác thông tin từ ảnh vé máy bay và điền vào hệ thống.
  • Luồng chat tạo Purchase Request hoạt động trơn tru trên Slack.
NGÀY 5: Kiểm Thử Tích Hợp (E2E), Xử Lý Edge Cases & Bàn Giao
Hoàn thiện & Go-Live

Công việc chi tiết trong ngày

  • Kiểm thử End-to-End (E2E): Chạy thử toàn bộ kịch bản từ lúc upload ảnh vé / tạo PR → dữ liệu vào Google Sheets & DynamoDB → sửa qua Slash Command Modal → báo cáo lỗi kiểm toán → bắn nhắc lịch 24h.
  • Xử lý các Edge Cases quan trọng:
    • Xử lý giới hạn timeout 3 giây của Slack bằng bất đồng bộ (Lambda Async Invocation).
    • Xử lý lệch múi giờ (Timezone) giữa sân bay đi và sân bay đến khi tính mốc 24h.
    • Cơ chế Retry & Rate Limit khi gọi Google Sheets API.
  • Viết tài liệu hướng dẫn sử dụng nhanh (Quick Guide) cho Biz Admin và chuẩn bị kịch bản Demo trực tiếp cho Sếp.

Kết quả bàn giao cuối Ngày 5

  • Hệ thống Production-ready trên AWS & Slack Workspace.
  • Kịch bản Demo trực quan đầy đủ 8 tính năng cho Sếp và đội Biz Admin.

Bảng Đối Chiếu 8 Yêu Cầu Nghiệp Vụ Với Giải Pháp Kỹ Thuật

# Yêu cầu trong Plan AWS Services & Công nghệ sử dụng Cách thức triển khai cụ thể
1 Dùng Google Service Account để Slack Bot tương tác Google Sheet GCP Service Account, AWS Secrets Manager, Thư viện gspread Lưu JSON key trên Secrets Manager, cấp quyền Editor vào Sheet cho email của Service Account.
2 Ingest dữ liệu từ Google Sheets vào DynamoDB qua Lambda AWS Lambda, Amazon DynamoDB Lambda đọc toàn bộ rows từ Sheet, chuẩn hóa schema và thực hiện batch_writer vào DynamoDB.
3 Tạo cronjob EventBridge hằng ngày, kiểm tra diff để update Amazon EventBridge Scheduler/Rules, AWS Lambda Tính mã băm row_hash cho mỗi dòng trên Sheet, đối chiếu với row_hash trong DynamoDB để chỉ update dòng thay đổi.
4 24h trước chuyến bay tự động bắn Email và Slack Bot DM Amazon EventBridge, AWS Lambda, Amazon SES, Slack WebClient (chat.postMessage) Quét các chuyến bay sắp cất cánh trong 24h tới, gửi đồng thời HTML Email qua SES và tin nhắn DM qua Slack User ID.
5 Nội dung gồm thông tin bay, đồ cần mang, AI gợi ý điểm vui chơi/đặc sản từ mã IATA Amazon Bedrock (Claude 3.5 Sonnet) Prompt truyền mã IATA điểm đến + thời điểm bay để AI sinh checklist hành lý và cẩm nang ẩm thực, thắng cảnh địa phương.
6 Kiểm tra thiếu field / sai format khi sync và báo cáo vào Slack channel mỗi ngày Pydantic Validator, AWS Lambda, Slack Incoming Webhook / Bot Kiểm tra từng dòng khi sync; tổng hợp danh sách dòng lỗi (số dòng, tên cột lỗi) gửi vào channel #biz-admin-alerts.
7 Interactive Modal + Slash Command để Admin sửa thẳng Google Sheet, test & automate Slack Block Kit Modal, API Gateway, AWS Lambda Lệnh /travel-admin bật Modal cho phép thêm/sửa dòng trực tiếp và có nút bấm kích hoạt chạy thử luồng Sync/Reminder.
8 Slack Bot Agent để user chat tạo Purchase Request hoặc upload ảnh vé máy bay tự điền field Slack AI Agent View, Amazon Bedrock Vision (Multimodal), Amazon S3 Nhận ảnh vé từ Slack, gọi Bedrock Vision bóc tách các trường thông tin chuyến bay hoặc hội thoại thu thập thông tin PR rồi điền vào Sheet.
